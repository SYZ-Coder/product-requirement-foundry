# 产品经理真实使用示例

这个示例不讲技术细节，只讲产品经理实际怎么用这套仓库。

## 场景

产品：社交 App

需求：

```text
希望在评论区优先展示用户关注的人发表的评论。
```

这类需求通常属于：

- `1->n` 增量需求

因为它不是从零做一个新评论系统，而是在现有评论区规则上做排序增强。

## 第一步：产品经理手里通常有什么

你不需要先写完整 PRD。

你通常只需要准备这些材料：

- 一句话需求
- 旧版评论区 PRD
- 当前评论区页面说明或流程说明
- 评论接口说明
- 评论埋点说明
- 术语表或评审纪要

## 第二步：怎么把这些材料交给这套工具

你可以把它理解成“把材料分类放好”：

### 需求本身

放到：

- `pm-input.zh-CN.md`
- 或 `pm-input.md`
- `baseline/request/request.md`

例如可以只写：

```text
在动态详情页评论区，优先展示用户关注的人发表的评论，提升熟人互动感知。
```

### 历史 PRD

放到：

- `baseline/prd/history/`

### 当前页面或流程说明

放到：

- `baseline/wiki/modules/`
- 或 `baseline/design/pages/`

### 接口说明

放到：

- `baseline/api/interfaces/`

### 埋点说明

放到：

- `baseline/tracking/events/`

### 术语表

放到：

- `baseline/glossary/`

你不需要一次放得特别完整。哪怕先有一句话需求 + 一份旧 PRD，也能开始第一轮。

## 第三步：让 AI 开始干活

在这之前，可以先运行：

```bash
node <product-requirement-foundry-root>/scripts/prepare-pm-input.js .
```

把 `pm-input.md` 自动整理成 `baseline/request/request.md` 和 `request.yaml`。

这一步产品经理可以直接对 AI 说：

```text
请先查看当前工作区里的 pm-input.zh-CN.md、baseline/request/ 和 baseline/ 下的历史资料，基于现有评论区能力，生成 docs/output/ 下的 PRD、影响分析、开放问题和可信度报告。
```

如果你们团队已经有人会用 Codex、Claude Code、Cursor 或 Copilot，就让对方在这个仓库里执行即可。

也可以把实际操作理解成下面 3 种方式：

### 方式 1：让会用 AI 工具的同事来操作

让同事打开这个仓库，然后把上面的提示词发给 AI。

### 方式 2：你自己在 AI 工具里打开项目

如果你自己就在 Cursor、Claude Code 等工具里打开了这个项目，也可以直接把上面的提示词发给 AI。

### 方式 3：把它理解成“让 AI 先看文件，再开始写”

重点不是只发一句需求，而是让 AI 先看：

- `pm-input.zh-CN.md`
- `baseline/request/`
- `baseline/` 下的历史资料

再开始生成结果。

## 第四步：你最终会看到什么

对产品经理来说，最值得先看的通常是这 4 份：

- `docs/output/prd.md`
- `docs/output/impact-analysis.md`
- `docs/output/open-questions.md`
- `docs/output/confidence-report.md`

## 第五步：你怎么判断结果好不好

重点不是看文风漂不漂亮，而是看这几件事：

### 1. 目标有没有写对

例如：

- 是不是明确在“动态详情页评论区”
- 是不是明确“优先展示关注的人评论”
- 是不是写清楚目标是“提升熟人互动感知”

### 2. 当前状态有没有写错

例如：

- 现在评论区是否已经有热度排序
- 是否已经有置顶、作者优先、好友优先等规则
- 新规则会不会和现有排序冲突

### 3. 影响范围有没有漏

例如：

- 评论列表排序逻辑
- 翻页或加载更多逻辑
- 无关注关系时的兜底逻辑
- 埋点是否要新增“熟人评论曝光”
- 灰度发布和回滚策略

### 4. 还有没有阻塞问题

例如：

- 多条熟人评论怎么排
- 熟人评论是否需要标识
- 作者本人评论和熟人评论谁优先
- 是否只在部分流量灰度

## 最后你可以怎么协作

产品经理最适合负责：

- 提供需求目标
- 提供历史资料
- 判断目标、边界和优先级
- 审核开放问题

AI 最适合负责：

- 把材料整理成结构化 PRD
- 补齐影响分析
- 列出潜在遗漏
- 把不确定点整理成开放问题

研发或会用 AI 工具的同事最适合负责：

- 帮你跑一遍仓库流程
- 生成 `docs/output/`
- 把结果继续交给开发流程

## 一句话总结

```text
你负责给目标和历史资料，
AI 负责整理成需求包，
你负责审结果并继续推进。
```
