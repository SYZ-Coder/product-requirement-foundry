# Code of Conduct

## Our Commitment

We want `product-requirement-foundry` to be a welcoming project for product managers, engineers, designers, analysts, and AI workflow builders.

Participation in this project should feel respectful, constructive, and safe for people with different backgrounds, experience levels, and viewpoints.

## Expected Behavior

- Be respectful and patient.
- Assume good intent, while still giving honest technical feedback.
- Focus criticism on ideas, behavior, and artifacts, not people.
- Be clear about evidence, assumptions, and uncertainty.
- Help others learn the workflow instead of gatekeeping it.
- Keep discussions aligned with the project goal: better, safer requirement generation.

## Unacceptable Behavior

- Harassment, insults, or personal attacks
- Discrimination or exclusionary behavior
- Repeated bad-faith arguing or derailing discussions
- Mocking beginners or dismissing domain questions
- Sharing private or sensitive information without permission

## Collaboration Standard

This project works best when contributors:

- separate facts from guesses
- document tradeoffs clearly
- explain compatibility risks kindly but directly
- improve the artifact, not the temperature of the discussion

## Enforcement

Project maintainers may remove, edit, or reject comments, issues, proposals, or contributions that violate this code of conduct.

If a discussion stops being constructive, maintainers may pause or close it to protect contributors and keep the project healthy.

## Reporting

If you encounter behavior that makes participation unsafe or unnecessarily hostile, report it to the maintainers through the repository contact path used by your team or hosting platform.

When reporting, include:

- what happened
- where it happened
- any relevant context or screenshots
- what kind of follow-up would help

## Scope

This code of conduct applies to repository discussions, issues, pull requests, reviews, examples, and related project communication spaces.
